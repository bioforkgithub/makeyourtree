# Example data

Four small synthetic datasets, each a tree plus one or two matching `.mytrack`
annotation tables. They exist so you can try the CLI, the layout modes and the
track stack without hunting for data first, and so the integration suite has
something end-to-end to run against.

> **Provenance.** Every file here was generated by `generate.py` in this
> directory, from a seeded random number generator and hand-written taxon
> names. Nothing was downloaded from, copied from, or compared against any
> other phylogenetics package's bundled examples or demo datasets — see
> this project. The trees are statistically plausible shapes, not real
> phylogenies, and the annotation values are noise. Do not cite them.
>
> Independent project; not affiliated with, endorsed by, or derived from any
> other phylogenetics package.

Regenerate everything with:

```
python examples/generate.py
```

The script is deterministic — re-running it reproduces these files byte for byte.

## The datasets

| Tree | Taxa | Format | What it exercises |
|---|---|---|---|
| `primates.nwk` | 16 | Newick, rooted, branch lengths + support | The ordinary case: a phylogram with a categorical strip and a numeric bar chart |
| `bacteria.nwk` | 24 | Newick, rooted, branch lengths + support | Wide multi-column tracks: a presence/absence matrix and a heatmap |
| `domains.nwk` | 7 | Newick, rooted, all edges length 1 | A cladogram-shaped tree with internal node names, plus a text track |
| `virus.nex` / `virus.xml` | 12 | NEXUS and phyloXML, same tree | Reading the same topology from two other formats |

### Annotation tables

| File | Track type | Notes |
|---|---|---|
| `primates_region.mytrack` | `color-strip` | Five categories with colours pinned in `[colors]`, so the legend order and the palette are fixed rather than assigned |
| `primates_bodymass.mytrack` | `bar-chart` | One numeric column with a value axis |
| `bacteria_resistance.mytrack` | `binary-matrix` | Six columns of `1` / `0` / `-1`; `-1` is *unknown* and renders as nothing at all, not as absent |
| `bacteria_expression.mytrack` | `heatmap` | Five columns on a diverging ramp, normalised across the whole matrix |
| `domains_labels.mytrack` | `text-labels` | Free text beside the tips |
| `virus_lineage.mytrack` | `color-strip` | Two pinned categories |
| `virus_titre.mytrack` | `gradient` | A single continuous column |

`virus.nex` and `virus.xml` hold the same tree, so either one works with the
two `virus_*.mytrack` tables.

## Try it

Summarise a tree, in text or as JSON:

```
makeyourtree info examples/primates.nwk
makeyourtree info examples/virus.xml --json
```

Convert between formats — detection is by content, and the output format comes
from the extension unless you override it with `--format`:

```
makeyourtree convert examples/virus.xml virus.nwk
makeyourtree convert examples/primates.nwk primates.nex
```

Render an SVG with both primate tracks attached:

```
makeyourtree render examples/primates.nwk primates.svg \
    --track examples/primates_region.mytrack \
    --track examples/primates_bodymass.mytrack \
    --ladderize desc
```

The same tree and tracks in each of the five layout modes:

```
for mode in rectangular slanted circular radial unrooted; do
    makeyourtree render examples/primates.nwk "primates-$mode.svg" --mode "$mode" \
        --track examples/primates_region.mytrack
done
```

Reroot before drawing:

```
makeyourtree reroot examples/primates.nwk primates-mid.nwk --midpoint
makeyourtree reroot examples/primates.nwk primates-out.nwk --outgroup Lemur_catta
```

## Two things worth noticing

**Support values on internal labels are ambiguous, and MakeYourTree says so.**
`primates.nwk` writes its support as internal labels — the usual Newick
convention — so reading it back prints

```
info: [newick.internal-label-ambiguous] 14 internal label(s) parse as numbers
and were read as branch support ...
```

That is the reader telling you it made a judgement call, not a warning that
something went wrong. Diagnostics go to stderr, so `--json` on stdout stays
pipeable.

**A cell that is empty or `-` means no value.** Tracks render it as a gap, never
as zero. `bacteria_resistance.mytrack` uses `-1` for a separate meaning — *unknown*
— which the binary matrix draws as nothing rather than as an empty outline.
